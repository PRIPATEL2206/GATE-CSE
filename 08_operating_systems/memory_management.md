# Memory Management & Virtual Memory

> Subject: Operating Systems
> GATE weight: **3–6 marks** every year. Paging, segmentation, TLB, page replacement, working set.

---

## 1. Concept Explanation

### 1.1 Memory Management Goals

- Allocate memory to processes.
- Protect processes from each other.
- Allow more processes than fit in physical memory (virtual memory).
- Translate virtual addresses to physical.

### 1.2 Address Spaces

| Term | Definition |
|---|---|
| **Physical address** | Actual RAM address |
| **Logical / Virtual address** | Address generated by CPU |
| **Address binding** | Map logical → physical (compile / load / execution time) |

### 1.3 Memory Allocation Strategies

#### Contiguous Allocation

| Method | Description |
|---|---|
| **Single-partition** | Whole memory for one process |
| **Multi-partition fixed** | Pre-divided regions |
| **Variable partition (MFT/MVT)** | Dynamically sized |

**Fragmentation:**
- **Internal:** wasted within block.
- **External:** gaps between blocks.

**Compaction** moves processes to merge gaps.

#### Allocation Algorithms

| Algorithm | Description |
|---|---|
| **First-fit** | First hole big enough |
| **Best-fit** | Smallest sufficient hole |
| **Worst-fit** | Largest hole |
| **Next-fit** | First-fit starting from last position |

### 1.4 Paging

Divide both virtual and physical memory into fixed-size **pages** (virtual) and **frames** (physical).

| Term | Description |
|---|---|
| **Page** | Unit of virtual memory (e.g., 4 KB) |
| **Frame** | Unit of physical memory (same size as page) |
| **Page number (VPN)** | High bits of virtual address |
| **Page offset** | Low bits |
| **Page table** | Per-process mapping VPN → PFN |

**Logical address** = VPN || offset.
**Physical address** = PFN || offset.

### 1.5 Address Translation

```
| VPN | offset |   ← logical
       ↓ page table lookup
| PFN | offset |   ← physical
```

For 32-bit VA, 4 KB pages: VPN = 20 bits; offset = 12 bits.

### 1.6 Page Table

Per process; maps VPN → PFN.

**Issue:** large for big address spaces (e.g., 2²⁰ entries × 4 bytes = 4 MB).

### 1.7 Multi-Level Page Tables

Split page table itself into pages.

For 32-bit VA, 4 KB pages, 4-byte PTEs:
- 2-level: outer 10 bits + inner 10 bits + offset 12 bits.

Save space when large parts of address space unused.

### 1.8 Inverted Page Table

One entry per **frame** (not per page).
**Tree of (PID, VPN) → frame.**

Saves space; lookup is hash-based.

### 1.9 TLB (Translation Lookaside Buffer)

Cache for page table entries; fast translation.

**TLB hit:** translation in TLB. **TLB miss:** consult page table; update TLB.

**EAT (effective access time)** with TLB:
```
EAT = h · (TLB time + memory access)
    + (1 − h) · (TLB time + page table access + memory access)
```

(Some formulations omit TLB time on miss path.)

### 1.10 Segmentation

Divide memory into **logical segments** of varying size (code, data, stack, etc.).

**Segment number + offset** addressing.
**Segment table** with base + limit per segment.

**External fragmentation** issue.

### 1.11 Paged Segmentation

Combine: segments divided into pages → no external fragmentation.

### 1.12 Virtual Memory

Allow programs to use more memory than physical RAM.

**Page** loaded on demand (demand paging).

**Page fault:** access to page not in memory → OS loads from disk.

### 1.13 Page Fault Handling

1. Check if page valid.
2. Find free frame (or evict one).
3. Read page from disk.
4. Update page table.
5. Restart instruction.

**Cost:** disk I/O is millions of cycles.

### 1.14 Page Replacement Algorithms

| Algorithm | Description |
|---|---|
| **FIFO** | Oldest page first |
| **Optimal (OPT)** | Page used furthest in future (theoretical) |
| **LRU** | Least Recently Used |
| **LFU** | Least Frequently Used |
| **Second-chance (Clock)** | FIFO + reference bit |
| **NRU** | Not Recently Used |
| **Aging** | LRU approximation |

### 1.15 Belady's Anomaly

In **FIFO**, more frames can lead to **more** page faults. Counterexample:
Reference string: 1,2,3,4,1,2,5,1,2,3,4,5.
- 3 frames: 9 faults.
- 4 frames: 10 faults.

**Stack algorithms (LRU, OPT)** don't suffer.

### 1.16 Working Set Model

**Working set W(t, Δ)** = pages used in last Δ time units.

**Strategy:** keep W in memory; thrashing avoided.

### 1.17 Thrashing

Excessive paging when total working sets exceed physical memory.

**Solutions:**
- Working set model.
- Page fault frequency control.

### 1.18 Page Fault Rate Calculations

Effective access time:
```
EAT = (1 − p) · ma + p · page_fault_time
```
where p = page fault rate, ma = memory access time.

**Example:** ma = 100 ns, page fault time = 8 ms = 8,000,000 ns.
For acceptable EAT (say 110 ns): p must be < 0.0000012 → very small fault rate.

### 1.19 Demand Paging

Pages loaded only when needed. Initially, none in memory; first access faults.

### 1.20 Copy-on-Write (COW)

`fork()` shares pages between parent and child; copy only when modified. Saves memory.

### 1.21 Memory-Mapped Files

File contents mapped to virtual address space; access via memory ops.

### 1.22 Important Memory Sizes (typical)

| Item | Typical Size |
|---|---|
| Page | 4 KB |
| Cache line | 64 B |
| TLB entries | 64–512 |
| L1 cache | 32–64 KB |
| Physical memory | 4 GB+ |
| Disk seek time | ~5–10 ms |

> **Summary:** Paging maps fixed-size pages to frames. TLB caches translations. Page table can be multi-level or inverted. Page replacement: FIFO/LRU/Optimal/Clock. Avoid thrashing via working set.

## 2. Important Points

- **Virtual address = VPN + offset.**
- **Page table** translates VPN → PFN.
- **TLB** caches recent translations.
- **Paging eliminates external fragmentation** but causes internal.
- **Segmentation can have external fragmentation.**
- **Demand paging** loads pages lazily.
- **Page fault rate must be very low** for acceptable performance.
- **LRU and OPT are stack algorithms** — no Belady anomaly.
- **FIFO** suffers from Belady's anomaly.
- **Working set** = pages used in last Δ time units.
- **Thrashing** when working sets exceed memory.
- **Multi-level page tables** save space for sparse address spaces.
- **Inverted page table** has one entry per frame.
- **Copy-on-write** shares until modification.
- **Memory-mapped files** use virtual memory for file access.

## 4. Formulas / Tricks

| # | Rule | Memorize Cold? |
|---|---|---|
| 1 | EAT = (1 − p)·ma + p·page_fault_time | ✅✅✅ |
| 2 | EAT (TLB) = h · (TLB + ma) + (1 − h) · (TLB + PT + ma) | ✅✅ |
| 3 | VPN = ⌈log₂(virtual size / page size)⌉ | ✅✅ |
| 4 | Multi-level PT splits VPN | ✅ |
| 5 | Belady's anomaly: only FIFO | ✅✅ |
| 6 | Stack algorithms (LRU, OPT): no Belady | ✅ |
| 7 | Working set window Δ | ✅ |
| 8 | Demand paging: load on first access | ✅ |
| 9 | Inverted PT: # entries = # frames | ✅ |
| 10 | Copy-on-write for fork() | ✅ |

### Tricks

- **For page replacement problems:** maintain frame state and trace step-by-step.
- **For LRU:** track order of access; evict oldest unused.
- **For Optimal:** look ahead, evict page used furthest.
- **For Clock:** use circular reference bits.
- **For paging address calculation:** offset bits = log₂(page size).
- **TLB miss penalty:** cost of page table access (or two for multi-level).

## 5. PYQs (with solutions)

### Q1. (GATE CSE 2017)
Page size 4 KB, virtual address 32 bits. # of pages?
**Solution.** 2³² / 4096 = 2²⁰.

### Q2. (GATE CSE 2014)
Belady's anomaly applies to:
**Solution.** FIFO.

### Q3. (GATE CSE 2018)
Optimal page replacement uses:
**Solution.** Future knowledge — evict page used furthest.

### Q4. (GATE CSE 2008)
LRU evicts:
**Solution.** Least recently used page.

### Q5. (GATE CSE 2010)
TLB hit ratio = 90%, TLB time = 10 ns, memory = 100 ns. EAT (assume one PT lookup on miss)?
**Solution.** EAT = 0.9·(10+100) + 0.1·(10+100+100) = 99 + 21 = 120 ns.

### Q6. (GATE CSE 2015)
Multi-level page table benefit:
**Solution.** Saves space when address space sparse.

### Q7. (GATE CSE 2013)
Demand paging:
**Solution.** Load on first access.

### Q8. (GATE CSE 2007)
Thrashing:
**Solution.** Excessive paging when working sets exceed memory.

### Q9. (GATE CSE 2003)
Page fault rate p, ma=100 ns, fault=8 ms. Tolerable p for EAT < 200 ns?
**Solution.** 200 = 100(1−p) + 8000000·p → p ≈ 1.25 × 10⁻⁵.

### Q10. (GATE CSE 2009)
Reference string 1,2,3,4,1,2,5,1,2,3,4,5 with 3 LRU frames:
**Solution.** Trace LRU; count faults.

### Q11. (GATE CSE 2019)
Inverted page table:
**Solution.** One entry per frame.

### Q12. (GATE CSE 2020)
Working set helps avoid:
**Solution.** Thrashing.

### Q13. (GATE CSE 2021)
Copy-on-write benefit:
**Solution.** Avoid copying until modification.

### Q14. (GATE CSE 2016)
Number of page table entries for 32-bit VA, 4 KB pages:
**Solution.** 2²⁰ entries.

### Q15. (GATE CSE 2011)
Page table size for 32-bit VA, 4 KB page, 4-byte PTE:
**Solution.** 4 MB.

## 7. Mistakes

| # | Trap | How to avoid |
|---|---|---|
| 1 | Paging causes external fragmentation | Internal only. |
| 2 | FIFO always worst | OPT theoretical best; LRU practical. |
| 3 | Belady's anomaly applies to all | Only FIFO (and similar). |
| 4 | Page table small | Can be huge for 64-bit. |
| 5 | TLB miss = page fault | Different events. |
| 6 | Demand paging loads everything | Only on first access. |
| 7 | Working set = constant | Changes over time. |
| 8 | Thrashing solvable by larger pages | Doesn't help directly. |
| 9 | Inverted PT lookups O(1) | Hash usually. |
| 10 | Copy-on-write copies always | Only on write. |
